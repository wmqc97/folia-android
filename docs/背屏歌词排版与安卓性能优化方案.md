# Folia 安卓适配 + 小米 17 Pro Max 背屏歌词优化方案

> 目标：在保留现有全部歌词效果与背景效果的前提下，降低安卓端卡顿与内存占用；
> 背屏歌词做到「画布铺满整屏、渲染中心右移、整句完整可见、不被摄像头硬切」。
> 本文只描述方案与验收口径，代码改动在确认后开始。
>
> 关联文档：`docs/背屏歌词适配方案.md`（v7，链路与投屏已落地）、`docs/背屏真机参数记录.md`（实测基线）。

## 0. 结论先行

1. **v2 已落地：画布固定为整屏，不再右扩。** `RemotePlaybackStage` 只对内容层做
   `translate(canvasX / 2, canvasY / 2) scale((347 - canvasX) / 347, (212 - canvasY) / 212)`，
   画布自身 offset 恒为 0；背景与效果继续铺满 0..347。
2. **旧实现的问题（保留作对照）**：画布右扩到 453、内容按 453 排版，classic 右溢 153px、
   monet 60px、claddagh 46px，cappella 有 2 块压摄像头。
3. **修法**：每个样式自己的 `canvasX / canvasY` 决定歌词画布；内容按「歌词画布 / 整屏」缩放，
   再平移到画布内渲染中心。左侧 0..canvasX 仍有背景与效果，不做「左侧整块不显示」的硬避让。
4. **全量审计（v2）**：14 个模式在 347×212、safeLeft 277→98、字号 100% 下
   `visibleIntruders = 0`、右缘不超屏；classic / partita / pendolo 的出厂例外见 §2.4。
5. **预览已同构**：固定 347×212 舞台 + 外层缩放，窗口里看到的位置就是背屏上的位置。
6. **背屏 WebView 现在加载的是完整 App**：`src/bootstrap.tsx` 静态 `import App`，
   背屏页虽然只渲染 `RearLyricsApp`，仍然把整个应用图（bootstrap 2.1MB、providerRegistry 1.3MB 等）
   装进第二个 JS 堆。这是背屏启动慢、内存高的最大单点。
6. **桥流量**：audio 20Hz + clock 4Hz，每次都是 `evaluateJavascript` + `JSON.parse`；
   config 携带整首歌词与队列。合并与降频有明确收益，且不影响观感。

## 0.1 参数确认（2026-10-21，真机截图）

| 项 | 数值 | 来源 |
|---|---|---|
| 背屏分辨率 | **976 × 596** | 背屏截图（com.xiaomi.subscreencenter） |
| 摄像头硬件右缘 | **277 px** | 摄像头位置图 |
| 系统 cutout 规避宽度 | **296 px** | 系统上报 |
| 代码当前取值 | **280 px**（`RearDisplayCommands.SAFE_LEFT_PX`） | 源码 |
| 换算 CSS（347 视口） | 277 → **98**；280 → **100**；296 → **105** | `safeLeftPx × 347 / 976` |

结论：

1. 真机当前用的不是 296，而是 280（CSS 100）。277 与 280 只差 3px 物理（约 1 CSS px），
   与 296 的差别也只有 19px 物理（约 6.8 CSS px）。**这 6.8px 不是「歌词被切」的原因**，
   真正的原因是 §1.2 的 453 宽排版盒。
2. 按你给的硬件位置收敛到 **277**：CSS 98，可见区 248.5×212，画布 445，中心 222.5。
   系统 296 保留为「原生取不到实测值」时的兜底。
3. 第一张截图是官方背屏中心，不是 Folia 歌词页；它的构图正好可以作为目标参考：
   背景铺满到摄像头下面，视觉主体落在摄像头右侧，左侧不出现被切断的内容。
4. 下面的审计表用的是 296（CSS 105）这一更保守的基线；换成 277 后每个模式的右缘溢出
   只会少 6.8px 左右，classic 的 153px 溢出仍然存在，修法不变。

## 1. 现状核对（代码 + 本地实测）

### 1.1 背屏链路

```
MainActivity（主屏）
  └─ useRearLyricsTransport / useObsBrowserSourcePublisher
       └─ RearProjection.publishSnapshot → 原生 evaluateJavascript
            └─ RearLyricsActivity（display 1，WebView ?rear=1）
                 └─ RearLyricsApp → RemotePlaybackStage → VisualizerRenderer
```

- 背屏实测：976×596、density 450、CSS 视口 347×212。
- 左侧安全带：系统 cutout 296 物理 = 105 CSS；代码当前 280 物理 = 100 CSS；
  按硬件位置 277 收敛后 = **98 CSS**。
- 可见区：296 基线 242×212；277 基线 **248.5×212**。
- 当前画布：296 基线 347 + 2×53 = 453，中心 226.5；277 基线 347 + 2×49 = 445，中心 222.5。
  两种取值下画布中心都等于可见区中心。

### 1.2 当前排版实现

- `RemotePlaybackStage`：外层 `absolute inset-0` + `right: -canvasExtraWidth`，画布铺满；
  内层 `absolute inset-0` 作为排版区，**没有收窄**，所以布局盒子 = 整块画布
  （296 基线 453，277 基线 445）。
- `stageViewport` 发布 `width = 453`、`offsetX = 53`、`visibleLeft/Right = 105/347`。
- 只有 `cappella` 用了 `useStageViewportVisibleWidth()`；其余模式按 453 排版。
- `classic` 的字号：`clamp(2.25rem, 6vw, 4.5rem)`，347 视口下 `6vw = 20.8px`，
  实际取 rem 下限 **36px**；7 字一行 = 252px，再加字间距与随机偏移，必然超出 242。

### 1.3 本地复现命令

```bash
npx vite --host 127.0.0.1 --port 4173 --strictPort
node dev/probes/rearSafeAreaAudit.mjs classic 1 _shots/audit-classic.json
node dev/probes/rearLyricsShot.mjs _shots/rear-classic.png 4000 rearLyrics '&mode=classic' 347 212 geometry
```

审计脚本会遍历真实文本节点，输出每块文字的落点、侵入深度、右缘溢出。
本次已跑完 14 个内建模式，结果见 §0 第 2 条。

### 1.4 预览不同构

`src/components/rear/RearLyricsStylePreview.tsx`：

- `resolveRearFrameTransform({ viewportInset: 0, ... })` —— 没有 105px 的平移；
- 容器是 `aspect-ratio: 976/596` 的自适应宽度，不是固定 347×212；
- 没有画布加宽（`right: -106px`）这一层。

结论：预览只能看「缩放 + 手动偏移」的相对变化，不能作为真机位置的依据。

### 1.5 安卓性能现状

已有能力（不需要重造）：

- `utils/frameRateLimiter.ts`：60/90/120 上限；
- `utils/frameTimingDiagnostics.ts`：p50/p95/p99、长任务、Long Animation Frame 归因；
- `pixiTextureBudget.ts` / `snapResolutionToTexturePool`：Pixi 纹理池分辨率吸附；
- `useMotionSettingsStore`：按动效面降级；
- `staticMode` / `paused`：暂停时静态化。

现存开销点（按影响排序）：

| # | 位置 | 现状 | 影响 |
|---|---|---|---|
| 1 | 背屏 WebView | 加载完整 App bundle | 内存 + 冷启动 |
| 2 | 桥 | audio 20Hz、clock 4Hz、逐条 JSON | 主线程 eval + 背屏 parse |
| 3 | 逐字动画 | `glowWordTiming` 每个词跑 `filter: blur()` | WebView 合成开销 |
| 4 | 全屏背景 | `FluidBackground` `blur(40px)` | GPU 采样 |
| 5 | 画布分辨率 | 各模式各自处理 DPR，没有统一的安卓上限 | 高分辨率机型显存/带宽 |
| 6 | 生命周期 | 页面隐藏/背屏不可见时没有统一停 rAF | 后台空转 |

## 2. 方案 A：背屏排版（v2，已落地）

> v2 取代了前面「加宽画布 + 画布 transform」的做法。用户确认的口径是：
> **画布恒等于整屏、不右扩、不超屏；左侧规避是每个样式自己的歌词画布起点；
> 渲染中心偏移在画布内部；适配靠字号 / 效果大小 + 渲染中心，不做左侧整块不显示的硬避让。**

### 2.1 模型

```
背屏 347×212
┌────────────────────────────────────────────┐
│ 画布：位置 = canvasX / canvasY（默认 0）     │
│ 画布尺寸恒为 347×212，可移出屏幕左/上（负数）│
│                                            │
│  ┌ 画布框（预览里用虚线画出来）─────────┐   │
│  │ 内容：原始大小，中心 = 画布中心     │   │
│  │ centerOffsetX/Y 只移动内容，不移动框  │   │
│  └──────────────────────────────────────┘   │
└────────────────────────────────────────────┘
```

内容层 transform：

```
画布层：
  translateX = canvasX
  translateY = canvasY
  scaleX = effectScaleX
  scaleY = effectScaleY
  transform-origin: 0 0

内容层（VisualizerShell 内部）：
  translate(centerOffsetX, centerOffsetY)
```

- **v4 不再有任何 safeLeft 自动偏移**：画布和内容都从屏幕 x=0 开始，左侧摄像头区域也是画布的一部分；
- `canvasX = 0` → 画布从屏幕 0 开始；负数继续往左，`canvasY` 同理；
- `centerOffset = 0` → 内容中心在画布中心（173.5）；负数往左/上；
- **渲染中心只加在 VisualizerShell 的内容层**，画布层 transform 里没有它；所以拖渲染中心时画布/背景/画布框不动，只有效果与歌词移动；
- 缩放只由 `effectScale` 控制，画布位置不参与缩放。

### 2.2 每个样式的设置

| 设置 | 字段 | 作用 |
|---|---|---|
| 字体 | `fontScale` | 该样式的字号倍率（叠在背屏全局字号上） |
| 画布 X | `canvasX` | 画布左缘，默认 0；负数往左（-200..240） |
| 画布 Y | `canvasY` | 画布上缘，默认 0；负数往上（-140..140） |
| 渲染中心 X | `centerOffsetX` | 内容中心相对画布中心，负数往左（-347..347） |
| 渲染中心 Y | `centerOffsetY` | 内容中心相对画布中心，负数往上（-212..212） |
| 效果缩放 X/Y | `effectScaleX/Y` | 内容大小；画布框不跟着缩放 |

全局左侧避让 `rearLyricsSafeLeftCss` 已从 UI / 导入导出移除，只在旧配置里保留字段、不再参与排版。
控制条与面板仍用原生实测的摄像头宽度定位。

### 2.3 代码落点

| 文件 | 改动 |
|---|---|
| `src/components/playbackStage/rearFrameGeometry.ts` | 新增 `resolveRearContentFrame` / `resolveRearContentTransform`，画布固定 |
| `src/components/playbackStage/RemotePlaybackStage.tsx` | 画布层只施加 canvasX/Y + effectScale；渲染中心作为独立 prop 传给 Visualizer |
| `src/components/visualizer/VisualizerShell.tsx` | 内容层单独 translate(centerOffset)，画布/背景/字幕不跟着动 |
| `src/stores/useTypographySettingsStore.ts` | 新字段、默认值、旧字段迁移、逐样式出厂例外 |
| `src/components/rear/RearLyricsApp.tsx` | 解析每个样式的 frame；歌词排版不再使用 `safeLeftCss` |
| `src/components/rear/RearLyricsStylePreview.tsx` | 固定 347×212 舞台 + 外层缩放，和真机同一份几何 |
| `src/components/rear/RearLyricsStylePlayground.tsx` | 移除全局左侧避让卡片；新增画布 X/Y、渲染中心 X/Y、效果缩放 |
| `src/components/rear/RearLyricsPanelCommon.tsx` | 背屏面板同一套逐样式滑杆 |
| `android/.../RearDisplayCommands.java` | `SAFE_LEFT_PX = 277` |

### 2.4 出厂例外（实测）

所有样式的出厂值统一：

| 字段 | 默认 |
|---|---|
| `canvasX / canvasY` | **0**（画布从屏幕左/上缘开始） |
| `centerOffsetX / centerOffsetY` | **0**（内容中心在画布中心） |
| `effectScaleX / effectScaleY` | **1x** |
| `fontScale` | **1x** |

不再有按模式的预缩放例外。左侧可能有一两个字压到摄像头带，这是「0 硬避让」的预期行为；
需要收小或右移时，用户自己调「效果缩放」或「渲染中心」，不改出厂值。

### 2.5 预览

预览不再自己算一套几何，而是：

- 以固定 347×212 渲染真实的 `VisualizerRenderer`；
- 挂载期间把全局舞台视口切成 347×212，visualizer 内部的字号 / 换行与真机一致；
- 外层按容器宽度 `scale(containerWidth / 347)`；
- 左侧摄像头带只作为半透明遮罩，不参与内容排版。

### 2.6 字幕

长句溢出审计暴露了共享字幕层：`inline-block` 的 shrink-to-fit 宽度会按 max-content 撑出屏幕。
已在 `VisualizerSubtitleOverlay` 的容器加 `max-w-full`，长句在可见区内换行 / 截断，
主歌词与字幕都不再从右缘溢出。

## 3. 方案 B：安卓性能

### 3.1 背屏独立入口（收益最大，风险低）

- 新增 `rear.html` + `src/rear.tsx`，只 import：
  `RearLyricsApp`、`index.css`、i18n、帧率限制器、必要 store。
- `vite.config.ts` 的 `rollupOptions.input` 增加 `rear: 'rear.html'`。
- `RearLyricsActivity.buildRearUrl()` 改为 `/rear.html?rear=1&...`。
- 同源（`https://localhost`），localStorage / IndexedDB 继续共享。
- 预期：背屏 WebView 不再解析 App / providerRegistry / stageLayers 等大 chunk；
  冷启动与常驻内存同时下降。

### 3.2 桥合并与降频

- 新增 `frame` 推送：`{ clock, audio }` 一次 `evaluateJavascript`，背屏一次 `JSON.parse`。
- 频率：播放中 15Hz，暂停 4Hz，页面不可见 0Hz。
- 频谱：背屏只需要 32 点（347 CSS px 宽，64 点没有可分辨收益）。
- config 继续走现有 `ObsBrowserSourceConfigPublicationTracker` 去重，只在变化时发。

### 3.3 安卓画质档

新增 `androidQualityTier: 'auto' | 'high' | 'saver'`（默认 auto）：

- auto 判定：`navigator.deviceMemory`、`hardwareConcurrency`、WebGL renderer 字符串；
  取不到时按 high 处理，避免误伤。
- 只降三类开销，不删效果：
  1. Pixi / Canvas 渲染分辨率上限（建议 2.0，主屏 3.5 DPR 机型收益明显）；
  2. 全屏背景模糊半径（40px → 20px）；
  3. 逐字 `filter: blur()` 改为 `opacity + scale`（视觉差异小，合成开销低一个量级）。
- 设置里提供「画质：自动 / 高 / 省电」，high 完全等价于现在的桌面画质。

### 3.4 生命周期

- 统一监听 `document.visibilityState` 与背屏 Activity 的可见性：
  不可见时停 rAF、停 analyser 轮询、停桥推送；恢复时重建。
- 暂停时继续用 `staticMode`，不额外新增状态。

### 3.5 WebView

- 主屏与背屏都显式 `setLayerType(View.LAYER_TYPE_HARDWARE, null)`；
- 关闭 overscroll（`setOverScrollMode(NEVER)`）；
- 背屏保持 `setMediaPlaybackRequiresUserGesture(false)`，不加载媒体；
- `setOffscreenPreRaster(false)`（默认值，显式写出，避免厂商 ROM 改默认）。

## 5. 验收口径

### 5.1 背屏排版

- 14 个内建模式，在 347×212、safeLeft 105、字号 100%/125% 下：
  - `visibleIntruders = 0`；
  - `rightMostBlock.right <= innerWidth`；
  - 主歌词完整可见，不需要横向滚动或裁切。
- 预览窗口与真机截图逐像素对照，中心误差 < 2px。
- 控制条与面板仍在 242 可见区内，不压摄像头。

### 5.2 性能

- 真机 `frameTimingDiagnostics`：播放页 p95 帧耗时、长任务数量在优化后下降；
  记录优化前后两组数据，不用「感觉更流畅」作为结论。
- 背屏冷启动：从 `am start --display 1` 到 `ready()` 的时间对比。
- 内存：`dumpsys meminfo` 对比主屏单独运行 vs 主屏 + 背屏。
- 20 次连续投屏/退出，无残留 WebView、无官方背屏中心未恢复。

## 6. 风险与回滚

| 风险 | 处理 |
|---|---|
| 文字盒收窄后长句换行变多 | 用字号 fit 抵消；逐模式审计，不搞一刀切 |
| 预览改为真实舞台后性能下降 | 预览只在设置窗口打开时挂载，关闭即卸载 |
| 独立入口与主屏初始化不一致 | 同源 + 共用 i18n/主题初始化；先在探针里验证 localStorage 读写 |
| 画质档被用户认为「效果变差」 | 默认 auto 只在中低端机降；high 档完全等价现状；设置可切 |
| 改动碰到 `@note` 注释 | 一律保留原样，不翻译、不删除 |
